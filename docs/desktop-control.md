# 桌面控制

让模型能看屏幕、动鼠标键盘、打开程序，但每一步都先口头问你。这一页讲它怎么工作、门槛在哪、管不到什么。

## 用起来是什么样

戴着耳机，双按右 Ctrl 进入对话，说"帮我打开记事本，输入 hello"：

> 它：**我想打开记事本，然后在记事本里输入文字 hello，可以吗？**
> 你：可以。（或按右 Alt）
> （记事本弹出来，hello 出现在里面）
> 它：输好了。

说"不行"（或按右 Ctrl），那一步就不做，它口头确认一句，继续等你的下一句话。

## 门槛在代码里

批准不靠模型自觉：**模型手里的桌面工具本身没有"直接做"这条路。** 每个工具（`voiceclaude/desktop.py`，一个挂在每条线上的 MCP 服务器）被调用时，第一步是把"要做什么"递给后台服务的本机控制端点（`POST /ask`，只对 127.0.0.1 开放），然后原地等。后台服务（`switchboard.py` 的 `gate` / `gate_batch`）先查权限表，再让窗口念给你听、听你的回答，把"可以"或"不行"递回去。工具拿到"可以"才动手；拿到别的（不行、没听清、超时、voice-claude 没在运行）一律不动，并告诉模型"用户没同意"。

提示词里也写着"每步会先问用户"，那只是让它说话更自然，不是门槛本身。

## 工具和它们怎么问

| 工具 | 权限项 | 会问你 |
|---|---|---|
| 看屏幕 `screenshot` | 看屏幕 | "我想看一眼屏幕，可以吗？"（截图会发给模型） |
| 点击 `click` | 点击 | "我想点一下记事本的保存按钮，可以吗？"——必须用一句话说清点的是什么，光给坐标不行 |
| 输入文字 `type_text` | 输入文字 | "我想在'无标题 - 记事本'里输入文字 hello，可以吗？"——念出目标窗口和内容；超过 60 字念开头再说一共多少字，全文显示在窗口里；输入的是路径时念最后一级 |
| 按快捷键 `press_keys` | 按快捷键 | "我想在'无标题 - 记事本'里按 Ctrl 加 S，可以吗？" |
| 滚动 `scroll` | 滚动 | "我想在浏览器页面往下滚，可以吗？" |
| 打开程序 `open_app` | 打开程序 | "我想打开记事本，可以吗？"——只认 `[desktop.apps]` 里的清单（自带记事本、计算器、画图、文件管理器、浏览器、VS Code、终端、设置），不接受任意命令 |
| 打开文件或文件夹 `open_path` | 打开程序 | "我想打开文件夹 figures，可以吗？"——用系统默认程序打开，完整路径显示在窗口里；程序和脚本（.exe .bat .cmd .ps1 .py .vbs .js .lnk .msi 等）一律拒绝，路径不存在直接回话 |
| 一串步骤 `run_steps` | 一次批准一串步骤 | 几步连起来念一次、问一次，按顺序做（见下） |

模型可以在申请前面加一句目的，比如"为了保存文件，我想按 Ctrl 加 S，可以吗？"。

**一串步骤**：一件事要两步以上时，模型把它们一次交上来（中间要截图看结果的才拆开）。

- 权限表里 `batch = allow`（默认）时问一次；设成 `ask` 就退回每步都问。
- 这串里只要有一个动作被设成"禁止"，整串都不做。
- 中间某一步失败，后面的步骤不做。
- 截图不能放进串里。
- 申请里窗口名只念一次。

## 回答怎么判定

- 整句都是同意的说法（"可以""好的""行""对，切吧""确定""没问题""OK, go ahead""yes please"……）→ 同意；右 Alt 或"可以"按钮也是同意。
- 任何一段带"不、别、停、没、算了、取消、等（等下、稍等、等会儿）、慢着、回头再说"或英文 no / not / never / wait / stop → 拒绝（"没问题""没错""不错"这类同意的说法除外），宁可错拒不错批："嗯，不行""不，错了""Yeah, no""好，等下"都算拒绝。右 Ctrl 或"不行"按钮也是拒绝。
- 其他回答——反问（"可以吗""可以？"）、同意后面跟着别的话（"好，跳过""OK, forget it""可以，但是先让我看看"）、听不出来——它问"可以，还是不行？"再听一次；两次都没听清算拒绝。
- 60 秒没回答 → 算拒绝。

用外放（`barge_in = false`）时，它会等自己把问题念完再开始听，免得把自己的问题当成你的回答。

## 权限表和通透模式

`config.toml` 的 `[permissions]` 里每个动作可以设成"每次问"（ask）、"不用问"（allow）或"禁止"（deny）。桌面动作默认"每次问"；"禁止"的直接拒绝、不问。改这张表本身也要口头批准（设置页的「权限」子页点一个新值，等于替你说一句"把点击的权限改成允许"）。

**通透模式**（`[permissions] transparent = true`，或说"打开通透模式"，开之前口头确认一次）：所有"每次问"的动作直接执行，"禁止"的仍然禁止，只有两类还会问，申请先说原因：

- **删除**："删除：…，可以吗？"——Delete、Shift+Delete、Ctrl+D 键；点的按钮名带"删除 / 移除 / 清空 / 废纸篓 / 回收站 / 卸载 / 格式化 / delete / remove / trash / discard"等；输入的文字是删除命令（`rm`、`del`、`Remove-Item`、`git clean`、`git reset --hard` 等）。
- **覆盖已有文件**："会覆盖已有文件 report.docx：…，可以吗？"——在 Windows 的"文件已存在，要替换吗"对话框里确认（点"是 / 替换"、按回车或 Alt+Y）；点"替换 / 覆盖 / replace / overwrite"；输入一个已经存在的文件路径，或者在另存为对话框里输入那个文件夹里已经有的文件名。另存为一个新文件不问。

判断看的是动作本身（`voiceclaude/risk.py`：按的键、输入的文字、命令、Codex 的文件改动），不听模型怎么描述；只有点击例外——程序读不到屏幕上真正的按钮名，用的是模型给的目标名。能认出的是常见情况：删除键、删除命令、名字带删除 / 替换 / 覆盖的按钮、输入一个已存在的文件路径、在"文件已存在，要替换吗"里确认；别的删除、覆盖方式认不出来，不会问。后台命令（`background_job`）和 Codex 的沙箱外命令、工作区外改文件（`codex_shell` / `codex_edit`）也走同一套判断。

## 安全阀

- 鼠标甩到屏幕**左上角**，鼠标键盘动作立刻停下，正在输入的文字也会停。
- 按住右 Ctrl 0.8 秒，所有线路和工具停下。
- 每个动作和你的答复都记在 `desktop.log`。
- voice-claude 没在运行时申请发不出去，所有动作一律不做。
- 整个关掉：`[desktop] enabled = false`。

右 Alt 单独按本来会激活前台程序的菜单栏（或 Windows 11 的按键提示）；voice-claude 在你按住右 Alt 时补发一个没有用途的按键，松开时就不会激活。输入文字和按键前，工具还会确认前台窗口就是申请里念的那个（被申请卡抢走焦点时先切回去），不是就不做。

截图会缩到 1280 像素宽发给模型，模型说的坐标按缩小后的图算，工具自己换算回真实位置（Windows 的显示缩放也由它处理）。

## 管不到的

- 模型本来就有命令行工具，理论上可以用命令打开程序。对策：提示词要求一律用桌面工具；`start`、`Start-Process`、`explorer` 这类命令和常见的删除命令在 Claude Code 的禁止清单里。这是减速带不是墙。
- 模型的命令行理论上也能直接调用 pyautogui 或系统接口动鼠标，或者读到后台服务的口令文件、自己回答申请。模型没有理由这么做，但这道门只管上面这些工具。
- 账号里的其他连接器（Docs、Drive、Chrome 插件）动起来不经过申请，所以语音会话默认不挂它们（`--strict-mcp-config --no-chrome`；权限表里 `other_connectors` 默认"禁止"）。
- Windows 11 的记事本会恢复你上次打开的文件，"输入文字"会输进当前前台的那个标签页。所以申请会念出目标窗口的名字，听清再说"可以"。
